# 共同验证访问能力

本轮已完成 280 个目录详情的元数据核对；全文通路不能按这 280 项一次性打勾。所有状态随订购、账号、网络和站点变化，表格是有日期的证据快照。

## 预计验证体量

按 252 个官方订阅入口估算，假设每库只找一个适用样本，每次定位、认证、读取、下载、检查和记录用 5–10 分钟：

| 验证范围 | 样本/场景数 | 预计人工工时 |
|---|---:|---:|
| 每库一个样本、当前网络 | 252 | 21–42 小时 |
| 每库三个样本、当前网络 | 756 | 63–126 小时 |
| 每库三个样本、校内与校外各测 | 1,512 | 126–252 小时 |

这是规划假设，尚未计入故障修复、账号申请、验证码等待、逐子库/表/年份授权验证。252 个入口也可能共享出版商，一个入口可能包含多个独立产品，不能按入口数精确推算授权单元。免费、试用、自建等 28 项和国泰安内部数据表尚未计入。

建议先选实际需要的 10–15 个常用库，每库两个代表性样本（约 1.7–5 小时），后续随使用补充。不要为了覆盖率批量下载整库；每次验证只取所需的小样本，国泰安导出可能消耗机构配额。

## 一次共创验证怎么做

1. 从 [访问表](access-matrix.md) 找官方入口，用 `whu_get_database` 核实状态与范围。
2. 用 `whu_open_database` 或珞珈检索得到实际入口；需要时在工具打开的窗口人工认证。
3. 通过 MCP 读取一个目标。论文记录 DOI/标题、出版商和年份；数据记录库/表 ID、最小筛选条件和字段。
4. 有权限时显式下载一份小样本；检查实际文件格式、非空内容、文件大小和 SHA256。预览与导出相互核对。
5. 用仓库的“数据库访问验证”Issue 模板提交脱敏结果，注明 **人工网页操作** 还是 **MCP 工具操作**。人工成功可帮助排障，但不会直接把程序下载列打勾。

维护者核实后更新 `docs/data/whu-catalogue.json` 和访问表的对应步骤、日期、版本与限制。单个成功样本不升级为整库保证；失败记录具体步骤及 error_code，不能据此判定武大未订购。重跑 `scripts/inventory_whu.py` 可更新本地元数据证据，发布快照时仅摘录必要字段并重新审核。

## 报告内容

提供目录名称/ID、项目版本、测试日期、网络类型（校内/VPN/校外）、认证方式、操作步骤、DOI 或库/表 ID、成功步骤、错误码，以及文件格式/大小/哈希即可。若重启后失败，请注明同一会话与重启后的差异。

不要提交密码、验证码、Cookie、Token、账号资料、真实 IP、带会话凭据的链接、浏览器 profile、完整论文或受限数据文件。原始运行报告与下载内容留在本机忽略目录 `verification/`；公开记录只保留验证事实。
